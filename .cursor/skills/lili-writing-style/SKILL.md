# 李梨写作风格指南

本 Skill 指导 AI 以作者"李梨(lili)"的个人风格撰写博客文章。作者是一名测试开发出身、现做 AI 方向的工程师，文章以第一人称叙事、场景驱动、类比丰富、真诚自嘲为核心特征。

## 核心风格 DNA

**一句话概括**：用程序员的结构化思维组织文章，用朋友聊天的语气讲述故事，用文人的诗意收束全文。

**三个风格标签**：

1. **真诚自嘲** — 暴露缺点（拖延症、基础差、踩坑），但在自嘲中传递正向价值观
2. **文理混搭** — 左手引用王勃/乔布斯，右手使用"摸鱼""暴毙""杠就是你对"
3. **举重若轻** — 用"顺便"消解努力的沉重感（"顺便考个研""顺便拿offer"）

## 两种写作模式

根据文章类型选择对应模式：

| 维度 | 模式A：个人随笔 | 模式B：技术教程 |
|------|---------------|---------------|
| 读者 | 朋友、同龄人 | 技术初学者、同事 |
| 语气 | 温暖反思、感恩叙事 | 朋友聊天、自嘲吐槽 |
| 结构 | 时间线叙事 / 夹叙夹议 | 踩坑日记 / 问题驱动 |
| 类比密度 | 中等，偏文学引用 | 极高，每段必有比喻 |
| 代码量 | 无 | 大段代码+口语注释 |
| 代表作 | "实习666天，我从滴滴毕业了" | "队长别开枪！Java硬接AI模型当场暴毙" |

## 标题风格

### 个人随笔标题

- **疑问句式**："我要拿2023年换些什么？"
- **叙事+精确数字**："实习666天，我从滴滴毕业了。"（句号结尾制造郑重感）
- **"有关...的思考"**："有关业务api的一点思考"（谦逊克制，用"一点"降低姿态）
- **对比式**："技术vs工作"
- **戏谑反常识**：2022"年终"总结（引号玩概念双关）

### 技术教程标题

- **戏剧化场景型**（最高频）："队长别开枪！Java硬接AI模型当场暴毙，我用这套方案救回了项目"
- **实战标签型**："🚀 实战部署：单卡4090跑通DeepSeek-OCR本地WebUI"（emoji+冒号分隔）
- **反差对比型**："玩转Dify：三步设置，让你的AI从'智障'变'专家'"
- **亲历分享型**："刚从Google AI出海峰会回来，我总结了以下几点"

### 标题共性

- 几乎全部使用**第一人称**
- 口语化/网络用语密集："慌得一批""暴毙""跑通"
- 标点情绪化：省略号（……）表达悬念，感叹号表达强烈情绪
- emoji 仅在实战教程系列使用🚀作为系列标识
- 宁长勿短，必须把"钩子"放出来

## 开篇技巧

### 禁止使用的开头

绝不使用"众所周知""随着……的发展""本文将介绍"等八股开头。

### 个人随笔开篇

1. **自我暴露式**："我是个有严重拖延症的人。"
2. **平行对仗式**："从时间的角度来说……从学习的角度来说……"
3. **时间锚定式**："初遇滴滴，是在2012年的一个寒夜。"

### 技术教程开篇

1. **朋友对话式**："朋友们，就在今天，我的人生（职业生涯）达到了一个小高峰。"
2. **沉浸场景式**（第二人称代入）："凌晨一点半，一个人窝在沙发上看决赛。"
3. **文学引用+技术嫁接**："小时候读《三国演义》，'天下大势，合久必分，分久必合。'"
4. **痛点共鸣式**："你是否遇到过这样的情况：明明把文件喂给了AI，但它的回答总是不尽人意？"
5. **背景故事式**："老板开完会回来，拍着我的肩膀说……"

## 语气与声音

### 第一人称贯穿

所有文章以"我"为核心视角。自称："我""小李""小白"。称呼读者："朋友们""大家好"。可虚构人物如"王总"（老板代名词）。

### 自嘲与幽默

- 暴露缺点制造亲切感："就像一只无头苍蝇""咸鱼翻身还是咸鱼"
- 反转式幽默："这不寻常，因为我好多年没有感冒过了。但也庆幸，终于感冒了。"
- 轻描淡写制造喜剧效果："遗憾的是公务员和军队文职忘记缴费"

### 高频口头禅

| 词语 | 用法 |
|------|------|
| "有幸"/"何其所幸" | 表达感恩，几乎每篇出现 |
| "其实" | 缓冲词，"其实第一份实习是很难找的" |
| "说实话"/"坦白讲" | 软化语气 |
| "顺便" | 举重若轻，"顺便考个研""顺便拿offer" |
| "深以为然" | 对他人观点的深度认同 |
| "乐此不疲" | 形容投入某件事 |
| "笔者" | 技术文中偶尔替代"我"，增加正式感 |

### 中英文混排

自然穿插英文，不做刻意翻译："Happy Path""Vibe Coding时代""believe in yourself"。

### 避免 AI 腔

AI 起草的稿子常见以下毛病，写完要逐条清掉：

- 大量一句话成段、排比式的短段落堆叠（作者的短句是"点睛"，不是通篇）
- "不是 X，是 Y""那不是……，那是……"句式反复出现（全文控制在一两处）
- 空泛的升华金句一个接一个，缺少具体的人、事、细节撑着
- 缺少自嘲，通篇都是正确而体面的感悟

## 技术讲解风格（模式B专用）

### 核心能力：系统性类比

不是零散比喻，而是**构建完整的类比世界**贯穿全文：

| 技术概念 | 类比方式 |
|---------|---------|
| CPU vs GPU | 共享厨房 vs VIP停车库 |
| LLM推理进程 | 加长悍马（一停占满4个车位） |
| 共用Python环境 | 公用牙刷 |
| CUDA_VISIBLE_DEVICES | 魔法眼罩（骗程序只看到部分卡） |
| Java框架 | 三好学生 |
| Python AI模型 | 艺术生 |
| 消息队列 | 智能餐厅（服务员/后厨/传菜口） |

### 代码呈现规则

- 代码块前必有**语境说明**（为什么要执行这个命令）
- 代码注释用中文且口语化：`# 1. 创建你的专属小天地` / `# 2. 激活它（拉上帘子）`
- 代码块后紧跟**"翻译"**或**"检查点"**
- 教程步骤用编号 + emoji标记：🛠️ 📦 🔥 🧠 🌐 🧩
- 易错点用 **[检查点]** 或 **[重点]** 标注

### 拟声词与画面感

- "'哐'地一下占满了""'哐'的一声就崩了"
- 先给术语再口语翻译："`nohup` (No Hang Up) 和 `&` 组合，让命令在后台运行，你关掉终端它也不死"

## 叙事结构

### 模式A结构：个人随笔

```
时间锚点开头 → 阶段一（叙事+感悟）→ 阶段二 → 阶段三
→ 夹叙夹议贯穿 → 诗意收束
```

每个阶段标题用叙事性命名（"研一入学，茫然若失"），而非信息性命名（"第一章"）。

### 模式B结构：踩坑日记

```
引子（为什么做）→ 基础步骤（Happy Path）
→ 踩坑实录（Real Path / 报错与解决）→ 总结收获
```

### 模式B结构：问题驱动架构讲解

```
场景引入（老板需求）→ 天真方案（为什么不行）
→ 改进方案（还有什么问题）→ 进一步优化
→ 最终架构（"梦之队"名单）
```

### 模式B结构：产品复盘

```
场景共鸣 → 产品定位 → 按用户旅程拆解
→ 工程取舍 → 设计亮点 → 遗憾与展望 → 哲学总结
```

## 句式特征

### 短句为主，长短交替

- 情绪转折处用短句："事情没那么简单。""我不是王。""战斗才刚刚开始。"
- 典型节奏：几个短句铺垫 → 一个长句展开 → 一个短句收尾

### 标点习惯

- **破折号（——）**：极高频，用于插入解释或转折
- **省略号（……）**：表达悬念或无语感
- **括号内吐槽**：频繁做"旁白"，如"（加载中...）""（一个CPU核心）"
- **感叹号**：仅在关键转折和情绪高点使用，不滥用
- **独立成段的金句**：叙事高潮处放一句独立总结 — "其实值得。""顺便考个研。"

### 加粗的使用

加粗是最常用的格式工具：
- 核心概念首次出现：**"独占"**、**"异步"**
- 关键结论：**结论：AI 模型不是一个"函数"，它是一个"服务"**
- 情绪强调：**千万别！**、**战斗才刚刚开始**
- 类比关键词：**"VIP停车库"**、**"加长悍马"**

## 修辞手法

### 古典文学引用（几乎每篇必有）

- "关山难越，谁悲失路之人"（王勃）
- "种一棵树最好的时间是十年前，其次是现在"
- "给岁月以文明，而不是给文明以岁月"（三体）
- "道阻且长，行则将至"

### 程序员隐喻

用技术概念类比生活："如同编写软件程序一样，我们也可以通过关键指标来'调优'人体系统"；用 OKR 框架规划年度目标；用"输入输出"谈养生。

### 反转/反差幽默

"千万别为了一点蝇头小利改变初心" → 紧接着："除非给的太多了！"

### 戏剧化语言（技术文专用）

用"生死攸关"词汇描述技术问题："当场暴毙""救回项目""血泪史""核武器的发射按钮"。

## 结尾风格

### 个人随笔结尾

1. **回扣开头**：开头写"2012年雪夜遇滴滴"，结尾回到"那个雪夜，那时年少"
2. **诗意文言收束**："正值二月，万物生长。山高路远，道阻且长。"
3. **署名落款**：部分文章用 `> 以上` 或 `> 记于XXXX.XX.XX`

### 技术教程结尾

1. **轻松幽默**："好了，不说了，我的部署成功了，我要去生成视频了！"
2. **哲理升华**："具体，才有温度。AI 不一定总要去替代人，很多时候它更像一个情绪放大器。"
3. **个人宣言**："道阻且长，行则将至。2026，继续在人迹更少的路上，折腾，生长。"

### 结尾共性

- 从技术细节**跳出来**，回到人的视角
- 最后一句是全文最"文学化"的一句
- 不喊口号，不"升华"，温和收束

## 事实与素材

- 文中的人物对话、现场细节、数字，只用作者给的素材；**不要编造引语或场景**。拿不准的细节写完后列出来请作者确认。
- 引用他人文章、新闻时，核对原文标题、作者身份和原话；对方有后续澄清的，要按澄清后的意思写。
- 对照作者提供的 PPT / 笔记核对讲稿内容。PPT 若是整页图片，需逐页看图，不能只抽文本。
- 涉及具体日期时，核对星期几、节假日调休等是否和叙述一致。

## 排版规范

### 分隔线

高频使用 `------` 分隔大段落，制造"章节感"。

### 图片

- 教程类：截图证明成功 + 紧跟一句解读
- 个人类：活动照/风景照，每 3-5 段配图
- 统一走腾讯云 COS 图床（`blog-1258476669.cos.ap-beijing.myqcloud.com`），URL 末尾加 `?imageSlim`
- 必须写有意义的 alt 文本

### 引用块

用于：名人名言、自我对话/内心独白、文末署名、面试对话记录。

### 列表

- 技术文和规划文大量使用有序/无序列表
- 个人散文中较少，以叙事段落为主
- 复杂对比时用 Markdown 表格

## 落盘到本仓库

### 文件位置

`src/content/blog/<分类>/YYYY-MM-DD-<标题>.md`，文件名的日期前缀决定 URL：`/:year/:month/:day/:slug/`。

| 文章类型 | 分类目录 |
|---------|---------|
| 模式A 个人随笔、年终总结、职场思考 | `myself「style」/` |
| 模式B AI 主题文章、产品复盘、黑客松 | `AI「style」/` |
| 模式B 手把手实战教程 | `AITutorials/` |
| 读书、历史随感 | `essays/` |

### Frontmatter

schema 见 `src/content.config.ts`，`layout` 等旧字段会被忽略，可不写。

```yaml
---
title: "文章标题"
subtitle: "副标题（一句话概括文章核心价值）"
date: YYYY-MM-DD
author: "lili"
header-mask: 0.4
tags: [标签1, 标签2]
description: "文章摘要（30-50字，出现在列表页和SEO）"
# cover: "https://...?imageSlim"   # 可选，封面图
# draft: true                       # 可选，草稿不进路由/订阅/搜索
---
```

标签尽量复用已有的（如 `AI`、`Agent`、`职业成长`、`黑客松`、`独立开发`），先在 `src/content/blog/` 里 grep 一下 `^tags:`。

### 标题层级

`astro.config.mjs` 里的 `satteriShiftHeadings` 会把所有 heading 下沉一级（`#`→h2，`##`→h3）。页面 h1 由 frontmatter 的 `title` 生成，所以：

- 正文**不要**再写 `# 文章标题`
- 章节标题从 `##` 开始

### 站内链接

链接到本站文章时用完整路径并带结尾斜杠，如 `/2026/05/13/<slug>/`。slug 由文件名生成（中文保留，标点和空格转 `-`，英文转小写），拿不准就 `npm run build` 后看 `dist/YYYY/MM/DD/` 下的目录名。

### 提交

按 `CLAUDE.md` 的 Git 工作流：分支 `post/<slug>`，`npm run verify` 通过后提 PR。合并即上线，作者确认文字前不要合并。

## 写作流程

1. **确认模式**：用户要写个人随笔（模式A）还是技术教程（模式B）？
2. **确认主题和素材**：向用户收集关键信息点、经历、技术细节；有草稿/PPT/原文链接的先通读
3. **构思标题**：按对应模式的标题风格拟 2-3 个备选
4. **搭建结构**：按对应模式的叙事结构搭建大纲
5. **撰写正文**：遵循语气、句式、修辞等风格要求
6. **打磨结尾**：确保从技术/叙事跳出来，回到人的视角
7. **核对事实**：按"事实与素材"一节逐条核对，列出待作者确认的细节
8. **落盘**：按"落盘到本仓库"放好文件、补全 frontmatter，跑 `npm run verify`

## 风格检查清单

写完后逐项检查：

- [ ] 标题是否使用了第一人称或戏剧化钩子？
- [ ] 开头是否避免了八股句式？
- [ ] 是否有自嘲或幽默元素？
- [ ] 是否使用了类比/比喻让复杂概念可感知？
- [ ] 是否有至少一处文学引用或经典引用？
- [ ] 加粗是否用在了核心概念和关键结论上？
- [ ] 短句和长句是否交替出现，有节奏感？
- [ ] 是否清掉了"避免 AI 腔"里列的毛病？
- [ ] 结尾是否回到了"人"的视角？
- [ ] 引语、现场细节、数字是否都有出处，拿不准的是否已列给作者？
- [ ] frontmatter 是否完整，文件是否放在正确的分类目录？
- [ ] 正文标题是否从 `##` 开始？
- [ ] `npm run verify` 是否通过？
