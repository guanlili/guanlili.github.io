## 博客格式

Frontmatter 以仓库 `src/content.config.ts` 为准。新博客草稿示例：

```yaml
---
title: "能由正文兑现的标题"
date: 2026-11-10
author: "lili"
subtitle: "可选的副标题"
description: "简述本文实际提供的内容"
tags: [工程实践]
draft: true
---
```

日期与标签应按本次文章填写，示例日期不是默认发布日期。正文未含完整计算或代码时，摘要不写“完整流程、附代码”。档案内部的确认、来源及可用范围字段不原样复制为对外文案。

- 页面文章标题来自 frontmatter；博客正文不重复文章标题。当前 `satteri-shift-headings.mjs` 对标题下沉一级并修正跳跃：新发布副本的一级章节可用 `#`、下一级用 `##`，核对构建结果应对应 h2、h3。保留旧稿时不为文风批量调整标题层级；源码规则有变化就以实际输出为准。
- 引用本站文章时保留原网址与结尾斜杠。无法确定 slug 时查看 `src/lib/permalink.ts` 或构建产物，不按显示标题猜网址。
- 图片优先用本次提供的、已可用的资源，配有意义的 alt。没有图片就省略或在稿外注明。
- 草稿先插入本地图片引用，供本人检查位置、可读性与脱敏效果。确认选图仍属于审稿。本人授权正式发布时，用本机 PicGo 的腾讯云 COS 配置上传仍为本地引用的最终配图，无需再逐张确认。已有可访问的 COS 链接直接沿用。本人明确要求提前上传时，按当次要求处理。上传使用既有博客图床，沿用仓库 `CLAUDE.md` 的域名和 `?imageSlim` 约定。
- 用上传返回的 HTTPS 链接验证能获取图片，再替换文稿中的本地引用。若上传或访问验证失败，保留本地引用并说明原因。上传配图和发布文章分别按本次授权执行。
- 排版服务阅读，不固定分隔线、emoji、配图频率或加粗金句数量。

## 同步与检查

修改已映射文章时，按档案“博客与档案同步约定”同轮维护两边，并运行：

```sh
python3 '/Users/guanhongli/Documents/LiLiArchive/04 内部资料/维护工具/同步博客.py' --check
```

来源单边变化先回收，双边冲突先合并；不覆盖并发编辑。新稿、改名、退役与跨平台独立改写不能靠普通同步自动完成，需维护相应映射、目录、可见性与引用。保留退役稿的排除状态，不意外恢复到推荐或默认取材。

仅改聊天里的文案不运行全站构建。改博客发布副本后，按仓库规则检查受影响内容；需要完整交付博客变更时运行 `npm run verify`。生成本地页面、构建通过或推送成功都不等于已经验证线上状态。

## 提交与发布

提交、推送、PR 与发布依当前任务授权执行；不因要求写稿、认可文字或历史上发过博客而自动执行。涉及 Git 操作时遵守仓库 `CLAUDE.md` 的分支与检查约定，保留无关的未提交变更。

`master` 更新会触发 GitHub Pages 部署；仅当本次授权包含上线时执行最终操作。上线后确认部署结果，核对相关线上页面。验证发布成功后，将主要原稿从“新稿”移到“文章原稿/历史博客/”对应分类，登记博客映射、检查引用并运行同步检查，再回填发布记录、网址与版本。只核验部分页面时写明范围，不声称全部旧网址逐项核验。
