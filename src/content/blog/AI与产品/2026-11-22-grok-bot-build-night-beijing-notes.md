11 月 20 日晚上，北京融科资讯中心。活动临近尾声，一位做运营的朋友上台，请大家拿出手机扫码，现场抽了个奖。

手机扫码参与，大屏实时开奖，整个过程不用填个人信息。工具是他自己做的。他没有技术背景，就用自然语言把现场需要的功能一项项交代清楚。我们在台下扫了一次码，也就知道这东西怎么用了。

我对这个小工具印象挺深。办线下活动，临时想加个互动环节，专门找研发排期有点重，现成的工具又未必顺手。最清楚大屏上该放什么、台下的人愿意点几下的，本来就是做运营的人。那天晚上，他自己把这几步走通了。

上一次参加几百人规模的社区 Meetup，台上分享的主要还是研发和产品经理。这次 Grok Bot Build Night 从七点半聊到十点多，上半场五位嘉宾带着 PPT 讲实践，下半场又有十位朋友现场报名。专门讲研发流程的差不多就我一个。其他人聊写医疗报告、做桌游、拍 AI 短片、跑海外地推，还有人带着手上的业务来找合作伙伴。

# 我那一段，讲的是怎么少在几个窗口之间传话

我第一个上台。手头的 AI 工具多了以后，我遇到过一个挺尴尬的情况。每个工具单独拿出来都挺快，合起来干活，我还得在几个窗口之间复制需求、贴结果、转达修改意见，末了再挨个检查一遍。几份活都有人干了，传话的人还是我。

我试着让 Grok Bot 接住这个入口。第一个例子就是这场活动的报名。我把链接扔给数字分身，让它从个人档案里找资料、填表，我在提交前看一眼。第二个例子是把小项目 Yujee 的海外邮箱登录改成国内手机号验证码登录。PM Bot 在群里协调研发和测试，我确认方案、提供阿里云密钥，最后拿真机验一次短信。

当晚的 16 页 PPT、逐页讲稿和委托公式，我整理在了前一篇博客里。[从数字分身到数字团队：我的 Grok Bot 工作实践](https://guanlili.github.io/2026/11/21/grok-bot-digital-team/)

我本来以为，后面几位大概也会聊研发和产品。刚一下台，下一位就开始讲她怎么用 Bot 做医疗行业的报告。

# 上半场的四组实践

## sunprise 给报告找了个主管，也把家里闲置的 NAS 用了起来

![6f0319f1558d56f0a818095f37b30364](https://blog-1258476669.cos.ap-beijing.myqcloud.com/macAir/6f0319f1558d56f0a818095f37b30364.jpg?imageSlim)

sunprise 在医疗行业工作，开场就说自己没有技术背景。她有些报告交得急，内容要有深度，呈现也得过得去。以前她会同时跑四五个 Agent，哪份能用、下一轮交给谁，每一步都要自己接。我听到这里觉得很熟悉，和我刚在台上讲的是同一种麻烦。

她现在先把目标和工作底线交给一个主管 Bot，让它建群，安排 Kimi、Codex 等不同模型接力。按她的分享，中间遇到模型额度用完，Bot 会记下进展，等额度恢复再接着跑，最后把报告交回给她审定。

她更喜欢的是 Bot 会跟着一件事往下走。有次它从日常对话里知道她周六有会，周五早上发了提醒，中午又来问要不要发言，顺手准备了发言要点和讲者背景。这场北京活动的名额，也是她人在外地时由 Bot 帮忙盯到的。收到个提醒当然挺好，省心的是事情没完，过一会儿它还能接着往前推一步。

她还让 Bot 帮忙联通家里的 Mac 和闲置设备，一晚上把 NAS 和 Obsidian 接起来。基础资料放 NAS，整理出来的笔记进 Obsidian，其他 Agent 可以按需调用和回写。攒了十多年的工作文件总算有了一个能开始整理的地方，她也不用一直守在电脑前，拿手机就能看进度。

涉及需要脱敏的资料，她会先在本地用小模型处理，处理完释放占用的内存，再把脱敏后的材料交给外部工具分析。她不熟悉网络配置，但哪份资料得先留在本地、报告最后得由谁审，都是她每天做这份工作积累下来的判断。具体怎么把流程接起来，她现在可以自己交代给 Bot，做出来再试。

她在台上管它叫「一个有记忆的大管家」。讲完报告和 NAS，她还提了几句用 ESP32 做生活里的小玩意儿，顺便推荐大家试试用语音交代任务。听她聊怎么用，我能明白她为什么先想到的是「管家」。手里这一件还没弄完，下一件就已经有人在帮忙留意了。

## 明月给自己凑了一桌会抬价的牌友

![130a6f8f5fd8c149fbf08161866280da](https://blog-1258476669.cos.ap-beijing.myqcloud.com/macAir/130a6f8f5fd8c149fbf08161866280da.jpg?imageSlim)

明月是软件工程师，分享的题目叫「一个人也能开桌」。她玩过一个德国的价值观工作坊，大概九十张卡，两两比较，从「自由」和「热爱」这样的选项里一路往下选，最后只能留一张。

她想在网页上玩，就让主 Bot 找来产品设计、全栈开发、测试和部署几个角色，自己在关键处提修改意见。按她的评价，最后做出来的功能跟自己手写差不多，美工还有得磨。

第二个尝试是《人生拍卖会》。每人手里有固定筹码，遇到想要的就竞价，拍下以后不能撤销，后面还可以交易。一个人玩，难就难在谁来和你抢。她干脆让主 Bot 当主持人、管流程和记账，再让它自己生成几个牌友，性格和偏好都提前瞒着她。

平时交代 Bot 干活，我希望它把要求理解得越准越好。到了明月这桌，大家要是太好商量，拍卖就没意思了。你以为能轻松拍下的东西，偏偏有人愿意再加价。明月说，玩游戏也是「见天地、见众生、见自己」。手里就那么多筹码，有了这几位真会争抢的桌友，你才得想想自己愿意为哪样东西再加一次价。

## 海博在群聊里给镜头分工

![a690410676efb4bd33ded301c2b42d1e](https://blog-1258476669.cos.ap-beijing.myqcloud.com/macAir/a690410676efb4bd33ded301c2b42d1e.jpg?imageSlim)

第四位是从外地赶来的大学生海博。他做 AI 视频工作室，平时接触短剧和宣传片。有些视频生产工具需要在节点画布里反复调参数和提示词，他更习惯从一段剧本出发，按拍片的工种把活交代下去。

他在群里安排了三类 Bot，下面再细分专岗。有人管景别和机位，有人做角色设计，有人琢磨镜头语言、光线和动作。需要一段画面，他就把剧本丢进去，交代这场戏要什么感觉。具体怎么布光、动作怎么衔接，由各个角色往下拆。他自己把精力放在创意、分工和审美判断上，提示词、生成、剪辑到交付等环节则按工作流推进。

现场他放了一段用这套流程做的成片，也提到作品获得过 AI 电影相关奖项。比起群里具体拉了几个 Bot，我更在意他怎么分工。什么镜头需要专门盯动作，什么地方得先把角色定下来，这些经验原来就用在片场和制作流程里。现在他把它们写进了自己每天发任务的群里。

## Chris崔睡前交代原型，后来我们戴着手表改它

![bcc57e4faec6d739789c601f742551c3](https://blog-1258476669.cos.ap-beijing.myqcloud.com/macAir/bcc57e4faec6d739789c601f742551c3.jpg?imageSlim)

Chris崔喜欢用 Apple Watch 随时录音记灵感。抬腕说一句很快，麻烦的是后面还要把录音导到 Get 笔记、转文字、整理成待办。她想做个叫 Daytime 的小工具，把手表记下的话通过 iCloud 同步到手机，生成当日待办，晚上还能翻看和复盘。

她睡前花了大概十分钟，跟 Bot 讲清手表端、手机端、电脑端各做什么，也聊了自己的商业模式设想。交代完她说：「你接下来有三个问题可以问我，问完今晚就开始干吧。」第二天醒来，她拿到了一版能用的东西。

后来我和她还有两位伙伴远程参加清华黑客松，迭代的就是 Daytime。四个人不在同一个场地，评审发现哪里有问题，直接对着手表说一句。语音转文字进待办，大家分头去 Git 上提 PR，再配合 Grok Bot 做整体代码评审。那天下午，我们发了三个版本。我挺喜欢这个用法。手上这一版哪一步还得停下来补操作，用它给下一版提需求的时候，当场就会碰到。

Chris崔还讲了一个团队场景。按她的分享，做出海增长的四人团队同时跟进十多家 B 端客户。各自的 Bot 接进飞书客户群，跟会议、处理基础工作和初步评审，最后的结论由人来定。一个人记录灵感和四个人服务多家客户，差得挺远。听她讲这两个例子，我记住的都是她把人在哪一步回来接手交代得很清楚。

# 下半场的十位即兴分享者

九点多开始自由报名。一小时里上来了十位朋友，很多人直接投屏，看他们怎么跑，有时也看看怎么跑砸的。

## 每天刷过去的信息，怎么留住一点

做自媒体的**苏乐**从官方模板起步。带着一件具体的事跑几轮，把容易做偏的地方一点点改过来，满意了再让 Bot 把这套流程写成 Skill。他拿每天要看的 X 信息做了份定时日报，指定领域和账号，下次连背景也不用重新交代一遍。

**金尘马**以前做研发，现在做自媒体和培训。他每隔三到六小时让 Bot 收一轮 X 上的热点，也会把推文定时同步到 Git 知识库，再推到 GitHub。浏览网页时碰到有用的内容，就用 Chrome 插件发给 Bot 归档。他还拿一道题试了五款模型，要求用代码做一段三分钟的无旁白动效，讲 BLG 从建队到夺冠。按他对这道题的评价，Claude Opus 的结果最好，Astra 和 GPT 也能用，Grok Bot 直接生成的效果一般，音效还有点「阴间」。同一份活试过几个工具之后，下次怎么分工就有数了。

**文子**是做自媒体的文科生，也是宝妈。她让几个 Bot 分头在 X 上找前沿消息、核实信息、整理选题，再把能用的内容带回国内平台和社群。微信群里碰到有价值的聊天，她就多选、合并转发给自己的社群小助手。小助手把它整理成卡片式日报，也能存到本地知识库。入口挺贴着她的日常，群里看到东西，顺手转发一下就能接着做。

iTab 开发者**新海**更在意下次聊的时候能不能接上这次。他把 Grok Bot 接到 Notion，分开存会议记录、学习和读书笔记、健康信息、语音日记。平时自动同步进去，等到要讨论相关事情时，Bot 可以先读他的背景和近期记录。他不用再从头解释自己最近在做什么。

## 多个 Agent 一起跑，怎么知道卡在哪儿

**Reno**最先碰到的是成本。没赶上低价订阅活动，重任务多跑几回，Token 花得挺快。他尽量在同一个对话里推进同一件事，复杂编码工作交给已经订阅的 Codex 或 Claude，在单独的稳定环境里执行。对他来说，执行环境稳定之后，剩下的问题就是几边怎么看见同一份进度。

他用 GitHub 任务卡记需求、上下文和状态。执行端领活、回传结果，调度端定期看进展、安排检查。这套方式后来也被他用到招聘里，跟进邮箱里的新简历，汇总候选人的匹配情况，准备面试问题，再用面试记录做复盘。

一位北信科大三、在面壁智能实习的同学，带来了自己的开源看板 **Luda**。他把写提示词、执行、验收拆成三类会话。执行端先自查，验收端再检查一遍，有问题就退回去改，连续失败才请人介入。任务跑到哪一步了，点开看板就能看到。需要纠偏时可以直接进一线会话，省掉请其他 Bot 层层转述。简单文档和重复任务用脚本或轻量模型，复杂活再调能力更强的模型。

**邱团长**把 Grok Bot 叫作自己的「参谋部」。手头已经买过的会员和 API 接进同一个入口，识图、分类、转写和配音按任务找工具，涉及需要脱敏的图片就先在本地处理。他还拿 Robotaxi 竞品周报举例，把原先的文字要点做成六十到九十秒的短视频，也展示了带多角色和环境音的广播剧。周报本来就要给别人看，听他讲完，我倒更想知道有多少人会点开、会看到哪儿。做到这一步，已经在琢磨同事会怎么用这份周报了。

## 工具做出来以后，拿去做点什么

做 AI 和数据运营的 **Ryan** 一口气讲了三个。第一个是 CACA Golf。他说打高尔夫录一小时，手动挑出击球片段可能也要剪一小时，于是用 Codex 做了个自动剪辑 App。按他现场给的数据，剪辑时间省下九成以上，上架 App Store 后累计约五千次下载。

推广时，他让 Bot 帮忙做社媒内容，一度一天发五十多篇，后来被平台限制到五篇。他也直说不少图文长得太像。另一边，他试过通过邮件联系欧美高尔夫教练和球馆，按他的说法，每天发一百到两百封，大概有一成回复，也带来了一些订阅。为方便把 App Store 优惠码发给别人，他还专门做了 CACA Dealer，把优惠码做成扫码就能领的卡片。剪辑功能有了，怎么让一个球友看到、愿意试、顺手把码领下来，又够他忙一轮。

另外两个项目更私人。他喜欢乐队「房东的猫」九年，赶上乐队十三周年生日会，就用家里 NAS 里的资料做了个纪念网站，把网址写进 NFC 钥匙链送给乐队。他还拿自家三只猫做宠物定制周边的样图，让 Bot 调研、定价，再把样品挂上闲鱼。那一单最后成不成，他上台时还在等真实买家的咨询。

开头那个现场抽奖工具，是做运营的**陆氏**带来的。他只讲了一会儿，就直接请大家扫一扫，让现场的人自己试。另一位第一次接触这类工具的 **Tina**，则在收尾时上来讲了三十秒。她做政企出海，想先把工具当日常助理用起来，也带着手头的业务来找能一起做本地部署的 OPC 团队。有些人已经拿着工具在找用户，她上来第一件事是说自己手头有什么活、缺个什么样的搭档。

# 散场后还记得的几件小事

回头看这十五场分享，我记得最清楚的是每个人动手前的那点麻烦。记完灵感还得回去整理一次，报告没改完就碰上模型额度见底，临时办个活动只想在大屏上开一次奖。要是只听别人讲有哪些模型、有几种工具，很容易漏掉这些细节。它们恰好决定了这个东西做出来以后，当事人愿不愿意再用第二遍。

那晚大家也挺愿意讲没做好的地方。明月说网页美工还得磨，金尘马直说有的模型做代码动效一般，Ryan 讲到发帖被限流时也把内容同质化的问题说了。做得多的人已经在给不同工具安排不同的活，本地模型处理部分资料，脚本干一遍遍重复的事，人在需要判断的地方回来接手。怎么搭要看手头的事，换一个场景还得再试。

下次再去这种 Meetup，我想多听一会儿台上的人原来是怎么干活的。一个抽奖工具，扫一次码就能弄懂。至于为什么想自己做一个，大概还得听听他以前办活动时，为了临时加这么一个环节，要来回找多少人。
